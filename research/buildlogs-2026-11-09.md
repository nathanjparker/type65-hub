## API notes (for the weekly task)

Tested 2026-11-09 via WebFetch (shell cannot reach the host).

**Works**
- `GET https://api.thefactoryfiveforum.com/api/build-logs/{id}` — returns log metadata, `description` (HTML opening post), `entries` (max ~20 native entries), `totalEntries`, `comments` (max ~40 top-level, each with `authorLocation`), `totalComments`, `milestones`, `entryRefs`, `commentRefs` (truncated title/preview lists for the remainder). Query params `?page=2`, `?pageSize=50`, `?offset=20` are ignored (same 20/40 returned).
- `GET https://api.thefactoryfiveforum.com/api/build-logs/{id}/entries/{entryId}` — returns one full native entry (`id`, `buildLogId`, `title`, `createdAt`, HTML text with images; `author` null). Verified on 16247/114424, 16247/114450, 16286/115022, 16328/114937. Entry ids within a log are mostly contiguous from the first id (e.g. 16286 → 115002…; 16328 → 114918…; 16247 → 114404…114477 per entryRefs) but late replies can jump (16328 intro entry 115802; 16389 has 113982–113991 then 115226–115227). Use `entryRefs` ids from the main response as the authoritative list, then fetch each.
- Only logs with `hasNativeEntries: true` (2023+ logs: 16247, 16286, 16328, 16389) have entries; 2014–2019 logs (15871, 15895, 15896, 15911, 16078, 16297) hold all builder updates as comments.

**Does not work (client_error / 404)**
- `/api/build-logs/{id}/entries` (with or without `?page=&pageSize=`)
- `/api/build-logs/{id}/comments?page=2&pageSize=50`
- `/api/build-log-entries/{entryId}`

**Unresolved**
- No working way found to page comments beyond the first 40; `commentRefs` previews are truncated. A per-comment endpoint (e.g. `/api/build-logs/{id}/comments/{commentId}`) was not tested and is worth one try next run.
